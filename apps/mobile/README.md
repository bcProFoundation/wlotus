# White Lotus — Capacitor shell (iOS + optional Android)

Wraps the live `https://wlotus.org` PWA in a native app shell via
[Capacitor](https://capacitorjs.com). `capacitor.config.ts` points
`server.url` at the live site (not a bundled copy of `apps/web/dist`), so —
like the Android TWA in `../twa` — every `npm run web:build` + deploy updates
the installed app instantly with no store resubmission.

## Why Capacitor (and why alongside the TWA, not instead of it)

There is no TWA-equivalent on iOS, so **Capacitor is the only realistic path
to an iOS App Store listing** for an existing web app without a full native
rewrite. For Android, the TWA in `../twa` is the primary/recommended listing
(real Chrome runtime — best fit for the WebGPU/WASM/Worker-based PoW mining
— and effectively zero native code to maintain).

The Android platform is still scaffolded here (`android/`) so this project
stays genuinely cross-platform and ready if a real need for native Android
plugins shows up later (push notifications, biometric confirm on burns,
secure keystore, etc. — none of which the TWA can host). **Don't publish a
second Android listing from here unless/until such a need arises** — running
both a TWA and a Capacitor build as two separate Play Store apps for the
same product is confusing for users and doubles the release/signing
overhead for no benefit today.

## What's committed here

- `capacitor.config.ts` — app id (`org.wlotus.app`), name, and the
  live-URL `server` config.
- `android/` — native Android Studio/Gradle project generated by
  `npx cap add android` (kept in git per Capacitor convention; its own
  `android/.gitignore` already excludes build output and the copied web
  bundle under `app/src/main/assets/public`).
- `ios/` — native Xcode project generated by `npx cap add ios` (same
  convention; `ios/.gitignore` excludes `Pods/`, `build/`, `DerivedData/`,
  and the copied web bundle).

Both platforms were added with `webDir` pointing at `../web/dist` purely to
satisfy Capacitor's CLI (it always copies *something* into the native
project as an offline-first fallback); the app boots from `server.url` at
runtime so this bundled copy is rarely hit. Run `npm run build -w @wlotus/web`
before `cap sync` if you want that offline fallback to be fresh too.

## One-time environment setup

### Android (works on Linux/macOS/Windows)

1. Install Android Studio (bundles the SDK) or the command-line SDK tools +
   `ANDROID_HOME`/`ANDROID_SDK_ROOT`.
2. `npm install` at the repo root (installs `@capacitor/*` — already a repo
   workspace dependency).
3. `npm run sync -w @wlotus/mobile` (alias for `cap sync android`).
4. `npm run open:android -w @wlotus/mobile` to open the project in Android
   Studio, or build directly with `cd apps/mobile/android && ./gradlew
   assembleDebug`.
5. For a signed release build, generate a keystore and configure
   `android/app/build.gradle` signing config (standard Android process —
   see [Capacitor Android docs](https://capacitorjs.com/docs/android)).
6. If you ever enable Android App Links (`intentFilters` with
   `autoVerify="true"` in `AndroidManifest.xml`) for this build, add its
   release-signing SHA-256 fingerprint as an additional entry in
   `apps/web/public/.well-known/assetlinks.json`.

### iOS (requires macOS + Xcode — not possible in this Linux sandbox)

1. On a Mac: install Xcode + CocoaPods (`sudo gem install cocoapods` or via
   Homebrew).
2. `npm install` at the repo root.
3. `npm run sync -w @wlotus/mobile` (runs `cap sync ios`, which also runs
   `pod install`).
4. `npm run open:ios -w @wlotus/mobile` to open `ios/App/App.xcworkspace` in
   Xcode. Set your Apple Developer Team under Signing & Capabilities.
5. Enable the **Associated Domains** capability with
   `applinks:wlotus.org` so Universal Links (tapping a `wlotus.org/<txid>`
   share link) open the app instead of Safari. This requires
   `apps/web/public/.well-known/apple-app-site-association` to contain your
   real Apple Team ID (replace the `REPLACE_WITH_APPLE_TEAM_ID` placeholder)
   and be deployed before Apple will validate it.
6. Build/run from Xcode, or archive for TestFlight/App Store submission.

## Apple Developer Program requirements (one-time, outside this repo)

- Apple Developer Program membership (annual fee).
- App Store Connect listing: screenshots, description, privacy policy URL,
  app privacy "nutrition label" declarations.
- TestFlight for beta distribution before public release.

## Updating the app after a web deploy

Nothing to do for either platform — both load the live site via
`server.url`. Rebuild/resubmit only when native config changes (icons,
splash screen, `Info.plist`/`AndroidManifest.xml` permissions, Capacitor
plugin versions).
